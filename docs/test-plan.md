# 검증 계획과 독립 정답

아래 기대값은 파서 실행 결과를 복사하지 않고 십진수 산술과 명시 초기상태로 작성했다. Astra 사양 승인: 2026-10-27. fixture는 합성이며 실제 회사 NC가 아니다. 구현·자동 시험 결과는 아직 별도 검증 대상이다. 단위 오차 허용은 |actual−expected| ≤ 1e−9 mm이며 null은 엄격 비교한다.

## 좌표 정답 fixture

각 code block의 첫 줄이 sourceLine 1이다. 별도 명시가 없으면 모든 초기 상태 unknown. 시작 좌표를 지정한 fixture도 unit/mode는 코드로 선언한다.

### P01 절대·P03 생략·P04 유형

초기 position=(0,0,0) mm를 사용자가 명시.

```gcode
G21 G90
N100 G00 X10 Y20 Z5
G01 X15
Y25 Z0
```

정답: line2 G00 (0,0,0)→(10,20,5), N100; line3 G01 (10,20,5)→(15,20,5); line4 G01 (15,20,5)→(15,25,0). 총 3구간, SUPPORTED.

### P02 증분

초기 position=(10,20,5) mm.

```gcode
G21 G91 G01 X5 Y-2
Z-5
```

정답: line1 (10,20,5)→(15,18,5); line2 (15,18,5)→(15,18,0). 총 2구간, SUPPORTED.

### P05 단위 전환

초기 position=(0,0,0) mm.

```gcode
G20 G90 G01 X1 Y2 Z0.5
G21 X50.8
G91 Y-25.4
```

정답: line1 끝=(25.4,50.8,12.7), line2 끝=(50.8,50.8,12.7), line3 끝=(50.8,25.4,12.7). 총 3구간, SUPPORTED. 기존 위치를 단위 변경 때 다시 환산하지 않는다.

### P06 원호

원호는 원본 모션 한 블록으로 저장하며 분할 점을 포함한다. G17에서 시작 (1,0,0), `G03 X0 Y1 I-1 J0`의 중간점은 (√0.5, √0.5, 0); G02로 (1,0)→(-1,0) 반원의 중간점은 (0,-1)이다. G18/G19의 오른손 방향, IJK 완전원, 부호 있는 R의 minor/major, 모달 이동과 오류 조건을 단위 테스트한다. 반경 1,000 mm 원호의 현 오차는 0.01 mm 이하로 검증한다. 명시 평면이 없거나 혼합 중심, 불일치 반지름, 모호한 R 완전원 및 과도한 분할은 진단하고 이후를 해석하지 않는다.

### P07 원문·주석

초기 position=(0,0,0) mm.

```gcode
G21 G90 (setup)
N10 G00 X1 ; first

N10 G01 Y2
G01 Z3
```

정답: sourceLine=[2,4,5], nBlock=["10","10",없음], 끝=[(1,0,0),(1,2,0),(1,2,3)]. 반복 N에도 ID/선택이 충돌하지 않는다. CRLF, UTF-8 BOM 변형도 동일 행/좌표.

### P08 매크로·좌표계 경계

초기 position=(0,0,0) mm.

```gcode
G21 G90 G01 X1
#1=10
G01 X20
```

정답: 첫 선만 PARTIAL, line2 진단, line3 생성 금지. line2를 G54, G43 H1, G81 X2, M98 P1, A90으로 각각 대체해도 같은 경계 정책.

### P09 초기 불확실성

```gcode
G21 G90 G00 X10
Y20
Z0
G01 X15
```

정답: 위치는 차례로 (10,null,null), (10,20,null), (10,20,0), (15,20,0). 첫 3행에 미확정 시작을 잇는 선 없음. line4에만 (10,20,0)→(15,20,0), PARTIAL 및 초기 미확정 경고.

추가: `G21 G91 G01 X5 Y-2`는 초기 좌표 없으면 확정 선 0개, unknown 유지와 PARTIAL. `G90 G01 X1 Y2 Z3`은 단위 없으므로 mm로 해석 금지. `G21 X1`은 motion/distance 미확정으로 선 생성 금지.

### P13 잘못된 문법

`G21 G90 G01 X1 X2`, `G90 G91 X1`, `G01 X1e999`, `G01 XNaN`, `(unclosed`, `G01 X1..2`는 INVALID. 잘못된 블록에서 부분 좌표 반영 금지. 완성된 prefix는 오류 상태에서만 유지한다. 매우 큰 유한값의 환산/누적 overflow도 차단한다.

## 2026-10-27 로컬 성능 실측

macOS의 headless Chromium, 1440×900, production preview에서 합성 G01 모션을 파일 입력 후 첫 화면 프레임까지와 다음 블록 버튼 반응을 측정했다. 사용자 데이터는 사용하지 않았다. 메모리는 브라우저 `performance.memory.usedJSHeapSize`의 대략적인 JS heap 값이며 GPU/전체 프로세스 메모리가 아니다.

| 모션 수 | 입력→첫 화면 | 다음 블록 반응 | 최대 long task | JS heap |
| --- | ---: | ---: | ---: | ---: |
| 1,000 | 386 ms | 79 ms | 165 ms | 10 MiB |
| 10,000 | 434 ms | 158 ms | 173 ms | 15 MiB |
| 100,000 | 1,029 ms | 141 ms | 409 ms | 93 MiB |

측정은 한 환경의 단일 실행이다. 항상 렌더링하던 뷰어를 상태 변경 시 렌더링하도록 바꾼 뒤의 수치이며, 기기·브라우저에 따른 재검증과 실제 현장 NC 검증은 별도로 필요하다.

필터·통계·비교 기능 통합 후 재측정한 동일 조건의 입력→첫 화면 / 다음 블록 반응은 각각 1,000개 386/78 ms, 10,000개 453/157 ms, 100,000개 1,043/161 ms였다. 100,000개 시험의 최대 long task는 402 ms, JS heap은 약 73 MiB로 관찰되었다. 실행 간 편차가 있으므로 수치는 성능 보장이 아니다.
