# G-code 지원 프로파일 — conservative-p1

이 문서는 제한적인 3축 G-code 해석 계약이다. 범용 CNC 컨트롤러 호환을 주장하지 않는다. 단위·좌표·거리 모드·이동 모드는 기본 unknown이며 사용자 명시 입력 또는 해당 G 코드로만 확정한다. 좌표는 내부적으로 mm, 숫자는 유한한 십진수만 허용한다.

| 문법 | P0 정책 |
| --- | --- |
| G0/G00, G1/G01 | 모달 급속/직선, 완전한 시작·끝 좌표일 때만 3D 선 생성 |
| G20/G21 | inch/mm; inch 좌표와 feed ×25.4로 내부 mm 환산 |
| G90/G91 | 절대/증분; unknown은 0으로 취급하지 않음 |
| X/Y/Z | 선택 축 갱신, 생략 축 보존; G91 unknown 축은 계속 unknown |
| G17/G18/G19 | plane 상태 추적; P0 직선 기하학에는 영향 없음 |
| F/S/T | 숫자 메타데이터만 추적; 실제 feed 시간·스핀들·공구 보정 효과 주장 없음 |
| N 정수 | 선택 block ID 문자열; 반복 가능, 원본 행 번호와 별개 |
| M2/M02/M30 | 프로그램 종료; 이후 비어 있지 않은 코드는 실행 경로에 포함하지 않고 진단 |
| 괄호 주석 / ; 이후 | 실행 문법과 분리. 괄호 불균형·중첩은 INVALID |
| % 단독 행 | 프로그램 경계 표식; 이동 없음 |
| G02/G03 및 I/J/K/R | G17/G18/G19 명시 필요; IJK는 시작점 기준 중심 오프셋, signed R은 양수 minor/음수 major. IJK 완전원 및 축 보간 지원. 혼합 R/IJK, 반지름 불일치, R 완전원은 INVALID; R 반원은 유일한 중심으로 처리 |
| G54–G59, G53, G92, G28, G41/G42/G43 및 해제 명령 | 좌표계·보정 의미 미확정, 미지원 경계에서 정지 |
| 사이클, 매크로, #, [], IF/GOTO, 서브프로그램, A/B/C/U/V/W | 미지원 경계에서 정지 |
| 기타 G/M/주소, block-delete / | 검증되지 않은 구문, 미지원 경계에서 정지 |

## 상태 전이

1. 블록의 전체 토큰/상충을 먼저 검증한 후 상태에 반영한다. 해당 블록의 단위·거리 모드가 같은 블록의 축 값에 적용된다.
2. G90은 알려진 단위에서 명시 축의 절대값을 확정한다. 생략 축은 그대로 유지한다. G91은 알려진 단위·현재 축에 한해 누적한다.
3. 모드/단위 미확정 이동은 정상 선으로 출력하지 않는다. 그 이동의 좌표를 unknown 처리하고 해당 지점에서 해석을 중단한다.
4. 시작이 미확정이어도 G90 X/Y/Z 전체 지정으로 끝 위치를 확정할 수 있다. 이 블록은 위치 확정 역할이며 미확정 시작점을 잇는 선을 생성하지 않는다.
5. 검증 범위 밖 원호·보정·좌표계·알 수 없는 코드의 영향이 불명확하면 해당 블록을 원자적으로 거부하고 이후 실행 해석을 멈춘다. 앞의 확정 경로만 유지하며 뒤를 임의 복구하지 않는다.
6. 중복 축/숫자 오류/서로 다른 같은 모달 그룹 명령/불균형 주석/비유한 수/계산 overflow는 INVALID. 잘못된 블록의 일부 좌표를 적용하지 않는다.

## 결과 분류

- SUPPORTED: 처리된 코드가 모두 지원 범위에 있고 모든 요청 이동을 확정 가능. 이동 없는 빈 입력은 별도 빈 상태로 안내한다.
- PARTIAL: 미확정 초기상태 또는 미지원 경계로 일부 이동을 표시할 수 없다. 확정 prefix/구간만 표시하고 경고한다.
- UNSUPPORTED: 미지원 경계로 표시 가능한 이동이 전혀 없다.
- INVALID: 문법/숫자 오류; 앞의 검증된 prefix가 있으면 오류 표시와 함께만 제공한다. 오류를 정상 완료로 표시하지 않는다.

원본 행은 1부터 시작하며 CRLF/LF를 지원한다. UTF-8 BOM을 제거하되 원문 행 매핑은 유지한다. 빈 행/주석도 행 번호에 포함한다. 행→구간은 1:N 배열 계약이고 현재 구현은 모션 블록마다 하나이며 원호의 분할점은 해당 블록에 포함된다. 모든 renderer 입력 좌표는 finite여야 한다.

## 원호 표시와 제한

G17은 XY, G18은 ZX, G19는 YZ의 오른손 좌표계 방향을 사용한다. G90.1/G91.1 등 중심의 모달 절대 지정은 지원하지 않는다. 원호는 한 모션 블록에 저장하며 최대 5도 및 기하학상 0.01 mm 현 오차를 기준으로 분할한다. 100,000개 선분을 넘어야 하는 원호는 추측하지 않고 INVALID로 중단한다. 원호 분할점은 전체 프로그램에서 최대 1,000,000개까지 허용한다. 표시용 Float32 변환의 3차원 위치 오차가 0.01 mm를 넘는 좌표는 진단하고 해석을 중단한다. 이 검사는 GPU 변환 단계 전체의 정밀도 보장은 아니다.

## LinuxCNC 부분 프로파일

사용자가 LinuxCNC를 선택했을 때 G61/G61.1/G64 경로 제어, G64의 P/Q 허용 오차, G4 P 정지 및 M3/M4/M5 스핀들 명령을 추가로 인식한다. G64 P/Q와 같은 블록에 이동 좌표를 함께 지정하는 경우는 지원하지 않는다. 이 명령을 허용해도 표시 경로는 블록의 지령 경로이며 G64 블렌딩을 포함한 실제 기계 경로는 계산하지 않는다. 일반 LinuxCNC 프로파일에서 M6 공구 교환, 공구 보정, 좌표계, G70/G71.2 및 일부 매크로 구문은 여전히 미지원이다. 일반 프로파일의 동작은 바뀌지 않는다. 선택한 프로파일은 다음 해석에 적용된다. LinuxCNC 명령의 의미는 [공식 G-code 문서](https://linuxcnc.org/docs/html/gcode/g-code.html)를 기준으로 한다.

LinuxCNC 프로파일은 수치 O-코드 서브루틴과 제한된 변수·표현식·while 반복을 실행 순서로 펼친다. 반복 횟수·호출 깊이·실행 단계에 상한을 두고 미지원 또는 오류가 있으면 기존 보수적 경계에서 정지한다. G76은 공구 반경 보정이 꺼진 G8 반경 모드, G18, 확정된 단위·위치·거리 모드와 회전 중인 스핀들이 있을 때만 나사 절삭을 직선 이동으로 전개하며, 각 이동을 원래 G76 행에 연결한다. 경로 전개는 스핀들 동기 구간과 예제 위상 정보를 보존한다. 실제 가감속은 계산하지 않는다.

내장 LinuxCNC 데모는 시작점 XYZ=0, G90/G8, G54=0, 공구 반경·길이=0, 위치 변경 없는 M6의 명시적 가상 설정을 사용한다. 이 설정에서 G92/G92.1을 고정 참조 좌표로 변환하고, G41/G42는 0반경이므로 경로를 이동시키지 않는다. 실제 비영 공구 보정이나 임의 공구표·작업 좌표계는 지원하지 않으며, 데모 설정을 실제 장비에 적용한 결과로 해석하지 않는다.

점 공구 참조 설정의 G71.1은 XZ·G8·G90·mm 숫자 윤곽으로 한정하며, 자체 계산에서 교점이 없거나 접점 간격이 0.000001mm를 넘으면 자동 조정하지 않고 중단한다. 같은 가상 설정의 G71.2는 XZ 숫자 직선·원호 윤곽, D 여유량, I/R 0.01mm 이상, 100개 이하 윤곽을 제한적으로 지원한다. A/C 코너는 아직 지원하지 않으며 교점이 불명확하면 중단한다. G70은 같은 설정에서 A/C 코너가 없는 XZ 숫자 직선·원호 윤곽과 D/E 여유량, 최대 100 패스를 지원한다. 좌표 방향 전환이나 검증 불가능한 접점은 중단한다. 명시적 선반 예제 공구표에서도 공구를 장착하고 반경 보정이 꺼진 상태라면 동일한 제한으로 G70/G71 경로를 계산하며 해당 공구를 소재 제거에 전달한다. 반경 보정을 켠 직후 또는 지원되는 선행 직선 보정 이동 뒤 G70은 보정 가능한 윤곽과 패스 간 큐가 지원 범위에 있을 때 D/E 여유량 및 다중 패스를 제한적으로 지원한다. 패스 간 급속 이동이 소재에 닿으면 소재 계산을 중단한다. G40 직후라면 사이클 전에 직선 이탈을 완료해야 한다. LinuxCNC 2.9.4는 보정이 켜진 G71을 거부한다. 검증 범위 밖의 보정 G70 큐 전환, 검증 범위 밖의 원호 간 연결과 공구표 X/Z의 비영 오프셋, 다른 버전과의 동등성은 지원하지 않는다.

G71.2의 제한된 직선 윤곽은 [LinuxCNC 2.9.4 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40462524673)에서 단순·단일 홈·이중 홈·경사 윤곽을 비교했다. G70의 단일·다중 패스 참조는 [별도 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40462562108)과, 원호와 여유량은 [원호 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40463917805)과 비교했다. 이는 명시된 점 공구 및 예제 좌표 설정에 대한 경로 검증이며 실제 공구 보정이나 완성 형상 검증이 아니다.

선반 예제 공구표의 반경 보정은 LinuxCNC 2.9.4의 [보정 참조 경로](https://github.com/good5229/nc_tracer/actions/runs/40464949783)와 선분, 접선 원호 및 G40 이탈을 대조했다. G41과 G42의 비접선 볼록 선분·원호 연결은 각각 [G41 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40507362704)과 [G42 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40507813406)을 대조했다. 오목 선분·원호 연결은 [오목 접점 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40510000414), 오목 원호 간 연결은 [원호 간 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40510388560)과 대조했다. 보정 중 G90/G91 전환도 제한적으로 지원한다. 직선 윤곽의 단일 패스는 [G70 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40480010891)과, 다중 패스와 여유량은 [다중 패스 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40509298848)과 비교했다. 명시적 예제 공구표는 T1/T2/T4/T9/T10의 직경 0.4mm, 방향 2, X/Z 길이 0과 고정 공구 교환을 가정하며 실제 기계의 값이 아니다.

선반 보정이 켜진 상태의 단독 M2/M30은 대기 중인 보정 경로를 내보내고 추가 이탈 이동 없이 보정을 해제한다. 이 동작은 LinuxCNC 2.9의 [종료 명령 설명](https://linuxcnc.org/docs/2.9/html/gcode/m-code.html)과 인터프리터의 종료 처리에 근거하며, 단일 윤곽과 다중 패스 G70의 단독 M2는 [LinuxCNC 2.9.4 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40518734540)과 대조했다. 종료 명령과 이동이 같은 블록에 있는 경우는 이 범위에 포함하지 않는다.

선반 소재 예제에서는 원형 공구 끝 외에 가상 인서트 단면을 선택할 수 있다. 이 단면은 Q2 공구에만 적용하며 원형 끝 중심 기준 꼭짓점 `(-r,0)`, `(0,-r)`, `(2,1)`, `(2,2)` mm의 볼록 다각형과 반경 `r`의 원을 합친 모양이다. 각 직선 구간에서 다각형을 연속적으로 쓸어 가고 원호는 기존 선분 근사로 계산한다. 일반 선반 이동은 각 셀 중심을 검사해 축 대칭으로 회전시킨다. G76 외경 나사는 원주를 48칸으로 나누고, 선단 각도 60도·깊이 방향 길이 2mm인 뾰족한 가상 공구와 동기화된 회전량으로 소재를 제거한다. G76의 급속 이동 중 스핀들 위상은 고정된 것으로 가정한다. 나사 피치 0.4mm 미만, 내경 나사와 비영 인덱스 위상은 중단한다. 실제 공구 날·홀더·고정구·스핀들 가감속 및 급속 중 회전은 검증하지 않으며 실제 형상이나 충돌 안전을 보증하지 않는다.

선반 소재는 고정 기본 원통 외에 데모 크기에 맞춘 가상 원통을 선택할 수 있다. G76 원본과 정확히 같은 텍스트에는 반경 3.175mm·Z -16.5~0mm·0.1mm 격자를, G70/G71 원본에는 반경 15mm·Z -40~3mm·0.2mm 격자를 초기 선택한다. 이는 NC에서 원재료를 추출한 값이 아니며 사용자가 변경할 수 있는 명시적 예제 가정이다. 격자 외곽은 셀 중심으로 판정하므로 실제 외경은 격자 크기만큼 차이날 수 있다.

공구 보정 진입 길이 오류 또는 원본 데모 참조의 G70 파고듦 오류 한 건으로 해석이 중단된 경우에는 사용자가 별도로 ‘중단 전 형상 계산’을 선택할 수 있다. 해석이 확인된 앞부분만 적용하며, 그 전에 급속 이동이 소재에 닿으면 해당 접촉 전 상태와 행을 표시한다. 결과는 완성 형상이 아님을 명시한다. 다른 중단 원인은 검증되지 않은 구간을 소재 계산에 포함하지 않는다.

원본 G70/G71 데모에 명시적 예제 공구표를 적용할 때만 LinuxCNC 2.9.4의 내부 윤곽 모사를 사용한다. 원본 텍스트를 바꾸지 않으며, 컨트롤러가 생성 윤곽에서 수행하는 접점 처리 및 작은 구간 생략을 재현한다. G71.1·G71.2와 G70 첫 패스의 출력은 해당 원본의 [LinuxCNC 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40510388560)과 대조했다. G70의 파고듦 오류와 예제 소재의 앞선 급속 접촉을 각각 표시하며, 중단 전 소재 결과를 완성품으로 표시하지 않는다. 다른 파일에는 이 참조 모사를 적용하지 않는다.

보정 선행 직선 이동 뒤 다중 패스 G70을 실행하는 한 가지 경로는 [LinuxCNC 2.9.4 참조 실행](https://github.com/good5229/nc_tracer/actions/runs/40519150427)과 대조했다. 선행 이동이 사이클 시작점에서 끝나는 참조 사례는 LinuxCNC에서 파고듦 오류가 나며, 현재 구현은 해당 큐 형상을 미지원으로 중단한다.
